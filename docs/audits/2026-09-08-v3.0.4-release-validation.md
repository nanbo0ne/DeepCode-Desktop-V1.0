# O.R.C.A. 3.0.4 Release Verification

This addendum supersedes the local-only release boundary in the earlier
[candidate report](2026-09-08-nextpatch-validation.md). The user subsequently
authorized official CNY pricing, real system DPI checks, and publication after
verification. The earlier report remains a record of its candidate build.

## Real Windows DPI

The native Wails executable ran with separate APPDATA, LOCALAPPDATA, HOME and
WebView2 data directories and no API credentials. Windows Settings changed the
system scale; browser zoom and emulated deviceScaleFactor were not used.
Read-only GetDpiForWindow measurements confirmed the scale received by Orca:

| Native window | DPI | Scale | Client coordinates | Result |
| --- | ---: | ---: | --- | --- |
| Modern, restored | 96 | 100% | 1240 x 721 | Layout inspected |
| Modern, maximized, right panel closed | 96 | 100% | 2560 x 1552 | Welcome centered, Composer aligned |
| Modern, maximized | 120 | 125% | 2048 x 1232 | Both right-panel states inspected |
| Modern, maximized, rebuilt executable | 144 | 150% | 1706 x 1018 | Layout inspected |
| Modern, live scale transition | 192 | 200% | 1280 x 752 | Native scale applied |
| Classic, restored | 192 | 200% | 1227 x 684 | Found status-bar overlap; fix required |
| Classic, live transition back | 144 | 150% | 1225 x 682 | Native scale applied |

All measured windows reported per-monitor DPI awareness (value 2). Coordinate
values are returned by the read-only observer; they are not claimed to be raw
physical display pixels. Modern Chinese draft input succeeded at system 200%,
without sending a request. UI Automation reported RootWebArea rather than the
focused textarea, so focus was verified with the visible caret and entered text;
UIA SetValue itself returned an automation API error and was not used as proof.

Normal native exit exposed a Wails divide-by-zero panic: OnShutdown queried a
destroyed window, whose DPI was zero. Geometry capture now happens in
OnBeforeClose; late asynchronous saves cannot overwrite the final state.
Rebuilt Modern and Classic both exited with code 0, and Modern geometry was
persisted. The older candidate reproduced exit code 2 before the fix.

Evidence: [Modern 150%](2026-09-08-nextpatch-evidence/native-dpi/modern-150.png),
[Modern 200% input](2026-09-08-nextpatch-evidence/native-dpi/modern-200-input.png),
[Classic defect at 200%](2026-09-08-nextpatch-evidence/native-dpi/classic-200-before-status-fix.png).

The user resumed desktop use and changed display topology during testing.
Settings was checked at 150% before stopping desktop interaction. The user's
topology change was not reversed. Classic 100%/125%, mixed-DPI cross-monitor
dragging, and a complete native interaction matrix are not covered. Earlier
128-case browser layout checks remain separate evidence, not native DPI tests.
The user subsequently asked to stop DPI work; no further scale changes or
native DPI checks are planned for this release.

The Classic status-bar fix passed 12 rendered checks in Chinese and English,
including a 660px component inside a wider viewport. No item overlap or overflow
was found, and secondary statistics remained available in the details popover.
The container rules are scoped to Classic. See [measurements](2026-09-08-nextpatch-evidence/status-render-results.json)
and [fixed Classic status bar](2026-09-08-nextpatch-evidence/classic-status-zh-1240.png).
