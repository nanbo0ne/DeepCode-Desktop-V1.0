# O.R.C.A. v3.0.1 全面测试与修复清单

日期：2026-09-07。状态：审计完成，尚未实施修复，不构成发布验收通过。

## 结论

现有前端测试和生产构建通过，但真实交互、异常注入和独立复现测试发现了它们没有覆盖的问题。优先处理以下五类：

1. 本地 AI 操作失败会把整个界面盖成崩溃页；暂停、取消后的下载缺少恢复入口。
2. Computer Use 停止没有取消在途动作；并发观察可能重新接受旧画面。
3. 模型供应商、CLI 工作目录及项目环境变量存在身份或目录串用问题。
4. Modern 的顶栏高度与布局占位不一致，侧栏按钮被遮挡；Classic 顶部控件仍会重叠。
5. 普通咨询存在不必要的工具调用和长篇叙述，需要同时改提示词、状态文案和信息层级。

详细 UI 与文案方案另见 [UI 与文案改进规格](2026-09-07-ui-copy.md)。本报告不把问题归因于某个历史模型；结论以当前实现与复现证据为准。

## 优先修复

P1：可能影响数据、控制安全或核心流程，应在下一次发布前修复。P2：功能或布局缺陷。P3：本地化和一致性改进。

### F01 · P1 · 本地 AI 安装失败触发全局崩溃界面

**浏览器故障注入复现。** 将 `StartLocalRuntimeInstall` 设为拒绝 Promise（模拟磁盘满），进入本地 AI 后点击安装。结果出现 `#crash-overlay`，而非页面内错误；正常会话界面被遮盖。

位置：`desktop/frontend/src/components/SettingsPanel.tsx:316-318`，同类下载、删除、暂停回调也采用 `.then(reload)` 而无 catch；全局处理在 `desktop/frontend/src/lib/crash.ts:38`。

修复：本地操作使用页面级 pending/error 状态和统一的错误处理；保留目录与任务数据；提供重试。不要把可预期的网络、磁盘、校验错误交给全局崩溃处理。

验收：安装/下载/删除/暂停/恢复/停止分别注入 reject，页面不崩溃、不重复提交、能继续聊天；刷新失败保留旧状态。证据：[安装失败截图](2026-09-07-evidence/install-error.png)、`browser-functional.json`。

### F02 · P1 · Computer Use 的停止未取消在途动作

**隔离复现。** 假输入后端进入阻塞动作后调用 `Stop`，会话已变为 cancelled，但动作收到的 context 没有取消；直到测试主动释放才结束。

位置：`desktop/computeruse/service.go:79-85,166-168,246-252`。启动时保存 session cancel，Execute 却传入调用者 context。

修复：动作与会话使用同一取消链；Stop/撤权应阻止新动作、取消当前动作并释放按键。不要仅更新 UI 状态。暂停的取消与恢复规则也需一致。

验收：阻塞动作必须在 Stop 后受限时间内退出；测试 Stop、Esc、撤权、窗口关闭以及停止后迟到的回调。真实 SendInput 延迟仍需专机测量，本次没有宣称已执行真实输入。

### F03 · P1 · 并发观察可能倒退到旧画面

**隔离复现。** 观察 generation 3 先返回，generation 2 后返回；当前 observation 被写回 2，随后基于 2 的动作被接受。

位置：`desktop/computeruse/service.go:105-132,152-154`。

修复：观察提交必须校验会话和单调递增的 generation，或串行化观察；动作同时核对最新会话代际。旧响应不能覆盖新状态。

验收：可控乱序、取消后返回、跨会话返回均拒绝；旧元素 ID 和旧坐标不能恢复为可执行状态。

### F04 · P1 · 完整模型引用失效后会静默换供应商

**隔离复现。** 请求 `deleted-relay/shared-model`，配置里只有其他供应商的同名模型，解析得到 `relay-a/shared-model`。没有真实请求发送到该假端点。

位置：`internal/config/config.go:2433-2445`、`desktop/tabs.go:1430-1439`。

影响：真实文件上下文、提示和费用可能改投未选择的端点。这与 V3 明确要求的供应商身份隔离相冲突，即使 helper 注释将其定义为 fallback，也应修复。

修复：完整引用失效时保留引用并要求重新选择；只允许显式、同一身份的官方旧模型别名迁移。

验收：同名模型、套餐与按量端点、已删供应商、角色模型恢复均不得剥离前缀跨来源选择。

### F05 · P1 · CLI 的 `--dir` 没有守住所指定的项目目录

**真实 CLI + DeepSeek 复现。** 父 Git 项目与 `nested` 目录都有 `audit-fixture.txt`；显式 `run --dir <nested>` 后请求读取该相对路径，期望 `ORCA_CHILD_84`，实际成功返回父目录的 `ORCA_READ_37`。

位置：`internal/cli/cli.go:161-167,183-215`，`internal/boot/boot.go:1133-1144`。CLI 先 chdir，却没有把显式目录传入 `boot.Options.WorkspaceRoot`，boot 又选择最近的 Git 根。

修复：显式 `--dir` 必须贯穿配置、工具、权限、会话、Skill 的根目录；仅未指定时采用 nearest Git root。

验收：父子有同名文件、不同项目配置时，读写均只作用于显式目录；不能只测试 cwd 已是 Git 根的情况。证据：`cli-explicit-dir.json`。此前隐式 cwd 的失败不单独计为缺陷。

### F06 · P1 · 项目 `.env` 在同一进程中串用

**临时目录隔离复现。** 项目 A 的同名变量为 `project-a`，B 为 `project-b`；顺序 `LoadForRoot(A)`、`LoadForRoot(B)` 后 B 仍拿到 A 的值。测试仅使用 `ORCA_AUDIT_PROJECT_KEY` 假变量。

位置：`internal/config/dotenv.go:22-68`。首次加载写入全局环境，后续又以已有环境优先，无法区分宿主环境和上一项目注入值。

修复：按工作区解析环境映射，启动 Provider/子进程时显式传入；不要把项目值长期混进进程全局环境。

验收：A/B/A 切换、同时打开两项目、宿主明确设置的环境变量优先级；密钥槽不能串用。与 F05 是不同问题，应分别回归。

### F07 · P1 · 首推 27B 模型的固定摘要与当前下载源不匹配

**实时元数据核对 + 代码确认，未下载大文件。**

### F08 · P1 · 一次通用验证会替代全部明确要求的测试

**隔离 Agent 复现。** 项目明确要求 `go test ./required` 和 `npm test`，模型只做成功写入与 `git diff --check`，便直接完成。

位置：`internal/agent/agent.go:741-755`、`internal/evidence/evidence.go:131-150,191-209`。每项命名检查都共用 `HasSuccessfulVerificationAfter(writer)` 兜底。

修复：保留“普通成功任务不重试三次”，但明确的关键检查必须由自身或明确等价的 receipt 满足。读取确认、diff 检查不能自动代表测试和构建通过。

验收：无显式契约时成功即可收尾；有两项契约时逐项匹配，不允许一个 receipt 满足所有检查；最终回答准确列出未运行项。

### F09 · P1 · Anthropic 流缺少终止事件仍被当作完成

**本地 HTTP 假服务器复现。** 发出一段合法文本 SSE 后正常关闭连接，不发送 `message_stop`；Provider 仍发 `ChunkDone`，没有中断错误。

位置：`internal/provider/anthropic/anthropic.go:405-436`。

修复：显式记录 message_stop；未见协议终止事件时返回可识别的流中断，不提交半截最终答案。不要以 TCP 正常 EOF 代替协议结束。

验收：文本截断、工具参数截断、正常 message_stop、错误事件、取消分别覆盖。没有真实 Anthropic Key，本条不是实网结论。

### F10 · P1 · 残留迁移锁会让 V11 迁移一直跳过

**临时目录复现。** 人为留下 `.orca-v11-migration.lock`，旧会话仍在；`EnsureV11StateMigration` 返回 nil，但没有迁移出新会话。

位置：`internal/config/state_migration.go:39-55`。

修复：锁应区分存活进程与崩溃遗留，并有超时/恢复提示；存在锁不等于迁移成功。还需检查中断复制留下的部分文件，不能仅因目标存在就跳过并写成功 marker。

验收：并发启动、崩溃残留锁、复制中断、校验失败与重启恢复；原目录完整保留。部分复制场景本次为静态待验，不冒充已运行。

### F11 · P1 · 旧凭据迁移失败后不再重试

**临时目录复现。** 配置文件先写成功，凭据目标因模拟路径异常写失败；再次迁移因新配置已存在而直接跳过。

位置：`internal/config/migrate.go:68-75,114-125`。

修复：配置与凭据采用可恢复的阶段记录，全部成功后才标记完成；重试不得覆盖用户后来新配的值。

验收：仅配置成功、仅凭据成功、权限错误、重新启动；保留旧文件；全部使用假凭据。

### F12 · P2 · Modern 顶栏和底栏没有正确占位

**浏览器尺寸与真实点击复现。** 在 1366×900、默认 modern/slate 中：顶栏高 76px，grid 第一行却是 46px；侧栏和正文从 y=46 开始。新会话按钮从 y=56 开始，上半部被顶栏盖住。底栏 y=870，高 30px，侧栏导航延伸到 y=892；点击最下面“设置”被 statusbar 截获。

位置：`desktop/frontend/src/styles.css:9700-9714,18320-18323`；Modern 的 `--statusbar-height:0px` 与实际全宽 30px 状态栏冲突。不是屏幕分辨率设置的问题。

修复：顶栏高度、grid 行和侧栏起点使用同一尺寸来源；底栏参与布局或明确预留空间。删除冲突规则，不能继续堆一层末尾覆盖。证据：[截图](2026-09-07-evidence/modern-shell-1366.png)、`shell-geometry.json`。

验收：顶栏 bottom 不大于正文/侧栏 top；“新建会话”“设置”中心点实际命中自身；760/1024/1366/1920、两语言、面板开关均测。

### F13 · P2 · Classic 顶部控件仍有重叠

**浏览器复现。** 760–1920px 多个场景中，搜索与右侧面板开关矩形相交 18–30px；较窄英文组合还有左侧操作挤占。

位置：`desktop/frontend/src/components/AppChrome.tsx:163-189`、`desktop/frontend/src/styles.css:14420-14557` 等共享 chrome 规则。浏览器预览按钮和真正原生窗口要分开验证，不能凭截图预览认定原生已完全一致。

修复：保留 Classic 独立 DOM/CSS 基线，用布局槽位为控件留空间；与 `desktop-v2.1.3` 做同数据、同窗口的视觉对比。V3 业务不能随视觉回退。

验收：旧版参考与 Classic 的顶栏、侧栏、Composer、状态栏逐项比对；控件命中区域不得相交。[Classic 760px 截图](2026-09-07-evidence/classic-running-760.png)。本次不声称已完成 V2 全页像素一致性验收。

### F14 · P2 · 设置加载失败永久显示“加载中”

**浏览器故障注入复现。** `Settings()` reject 后常规设置只有“加载中…”，没有错误或重试。

位置：`desktop/frontend/src/components/SettingsPanel.tsx:53-56,108-127`。

修复：首次读取与刷新使用明确的 loading/ready/error 状态；保留上次值；显示“设置未能加载”和重试入口。验收网络/桥接失败后恢复，不显示空白成功。

### F15 · P2 · 设置弹窗缺少焦点约束

**浏览器键盘复现。** 两样式×两语言中，55 次 Tab 有 28 次落在弹窗之外，包括背景菜单、项目和窗口按钮；无 dialog role/aria-modal。

位置：`desktop/frontend/src/components/SettingsPanel.tsx:109-120`。

修复：增加语义、初始焦点、循环焦点、背景不可交互及关闭后焦点归还。Esc 关闭设置和全局停止需有明确定义，不能互相吞掉。

验收：Tab/Shift+Tab 不逃逸；打开菜单或子弹窗也能返回；屏幕阅读器能读到标题。

### F16 · P2 · 下载暂停、取消后失去继续操作入口

**浏览器 fixture 复现。** paused 任务没有恢复和取消按钮；cancelled 任务让“下载”持续 disabled，没有重新下载入口。

位置：`desktop/frontend/src/components/SettingsPanel.tsx:325-353`。`active` 不包括 paused，而任何已有 task 都禁用下载；queued/verifying 反而出现继续按钮。

修复：按状态明确映射操作；paused 可继续/取消，failed 可重试/查看原因，cancelled 可重新下载，verifying 不应恢复下载。[暂停截图](2026-09-07-evidence/paused-download.png)。

验收：queued/downloading/paused/verifying/completed/failed/cancelled 全状态、重启恢复、按钮请求失败。

### F17 · P2 · 单个非 NVIDIA GPU 的输出可能解析失败

**PowerShell 输出格式复现 + 解码代码确认。** 与实现相同的单对象管线输出 `{...}`，Go 却只接受 `[]struct`，解码失败后返回 nil。

位置：`internal/localai/hardware_windows.go:84-105`。本机多 GPU 列表正常，不能据此排除单核显设备缺陷。

修复：输出强制数组或兼容对象/数组；区分“检测失败”和“没有显卡”；不可默认 gpu0 是目标独显。还需补真正 DXGI 显存预算能力，而非把 AdapterRAM 当实时可用预算。

验收：Intel/AMD 单卡、核显+独显顺序颠倒、虚拟显示适配器、nvidia-smi 不可用。真实 AMD/Intel 设备未在本轮覆盖。

### F18 · P2 · 普通咨询被过度工具化、结构化

**真实 CLI 单样本。** 问“你好，我想用这个软件整理读书笔记，可以怎么开始？”：4 次 Provider 请求约 32 秒，先调用系统信息、目录命令（一次失败后再试），再 ask，最后输出多节目录模板和“零风险上手”等话术。

证据：`cli-copy-probe.json`。这是 CLI 默认 profile 的一个样本，不是对所有桌面模式的统计，也不能证明某个历史模型是原因。

修复方向：咨询先直接回答；不需要本机事实时不查目录；简单问题用短建议和一个明确下一步。只在用户要创建文件、模板或工程方案时展开。复杂任务仍保留必要的验证和安全说明。

验收：固定普通咨询、解释、写作、实际修改任务语料；评估无关工具次数、重复叙述、首个有用答案耗时和内容正确性。禁止仅用“字数更短”评价质量。具体替换见 UI/文案规格。

### F19 · P3 · 新增设置页面中英文混杂

**浏览器英文页面观察 + 静态确认。** Local AI、Computer Use、About 的导航、按钮、说明仍有整段硬编码中文；窗口按钮 aria-label 在中文界面仍为英文。

位置：`desktop/frontend/src/components/SettingsPanel.tsx:288-380,399-416`、`AppChrome.tsx:348-353`。

修复：所有用户可见字串纳入同一 i18n；API 状态映射成人话，技术详情可展开。验收整页中英文截图及屏幕阅读器标签。

### F20 · P2 · CodeGraph 测试没有正确隔离开发机环境

**全量失败及定向重跑复现。** `TestApplyMCPModeRecordsCodegraphConnectFailure` 和 `TestSetMCPServerTierEnablesCodegraphAndIgnoresLegacyTier` 期望找不到 runtime，却取得空 failures；临时数据库清理时还被占用。

位置：`internal/cli/mcp_test.go:456-483`、`desktop/app_test.go:1958-2000`。测试使用 `DEEPSEEK_ORCA_CACHE_DIR`；当前解析器读取的是 `ORCA_CODEGRAPH_CACHE_DIR` / `DEEPSEEK_ORCA_CODEGRAPH_CACHE_DIR`（`internal/codegraph/install.go:39-55`）。

修复：使用真实生效的隔离变量并断言解析路径，屏蔽旁置 bundle；显式关闭测试拥有的 Host/子进程后再清理目录。

验收：装有/未装 CodeGraph 的机器均能重复通过，无文件锁残留。当前证据不证明正式桌面 CodeGraph 永久泄漏，不能把测试失败误报为全部 CodeGraph 不可用。

## 设计与维护观察

- **自动审批故障回退**：已隔离确认分类器失败会 fallback allow；这是此前计划明确要求保留的行为，不作为“未按计划实现”的 bug。本次建议评估改为人工确认，并说明取舍；不得擅自推翻策略。deny/显式 ask 仍优先。
- **Computer Use 能力提示过于乐观**：Windows 返回全部 capability=true，但相关 hook/捕获可能直到启动才失败。应区分“平台支持”和“已检测可用”。
- **本地 token 生命周期**：`ORCA_LOCAL_API_KEY` 写入全局环境后停止未清除。旧服务停止后 token 通常已无用，但不应向无关子进程继续传播；优先在进程内绑定 Provider。
- **开发开关**：`ORCA_DEV=0/false` 也关闭单实例锁，建议只认明确真值；本次未并开生产账户两实例。
- **更新文档与实现**：生产目前是通知并打开 GitHub 下载页；部分 desktop README 仍描述签名 manifest/self-update。应统一文档和 stable/canary 行为，不误称为“当前自动安装了未经校验的文件”。
- **历史发布文件**：旧品牌 1.0.x 安装器属于历史资产，不计为当前 UI 旧品牌残留。后续发布收集应显式限定版本，不能遍历目录随意上传。
- **Classic 基线**：当前存在独立 DOM 分支，但共享样式末尾仍有无条件覆盖。蓝白配色恢复不等于布局完全恢复；需要实际 V2 基准图和尺寸契约。
