# Work 产物运行时

O.R.C.A. 在助手模式和 Orca 中提供 DOCX、XLSX、PPTX 与 PDF 文件生成和结构化编辑。文件生成由 Go 内核完成；真实页面预览有独立的依赖和能力限制。

## 能力边界

- `artifact_create` 从结构化正文、工作表或幻灯片数据创建文件，并写入 `.orca-artifact.json` sidecar。
- `artifact_edit` 读取 sidecar 后执行追加文字、替换文字、设置单元格和增加幻灯片等结构化修改。
- `artifact_preview` 使用本机 PATH 中的 Poppler `pdftoppm` 渲染 PDF 首页为 PNG。未安装时明确报错；目前不提供 Office 文件的内置渲染器，也不再用占位图冒充文件预览。
- `artifact_validate` 重新打开输出文件，检查摘要、ZIP/OOXML 关系和文件结构；只报告能够从文件可靠确定的计数。
- 每次创建和修改都会在返回前重新解析并验证；验证失败不会报告成功。
- 结构检查通过不代表版面正确。PDF 首页预览也不代表已经检查其余页面；重要文件应在目标阅读器中检查完整内容和分页。

## 字体与依赖

文件生成不要求 Python、Microsoft Office 或 LibreOffice。OOXML 文件声明拉丁与东亚字体回退，由打开文件的 Office 套件选择本机字体；PDF 使用标准 CJK CID 字体引用，不嵌入商业字体。

PDF 预览需要用户另行安装 Poppler；主安装包不分发该工具。预览失败不会阻止已经成功生成的文件被正常打开，也不会被报告为视觉验收通过。Office 文件请用兼容的 Office 阅读器检查，字体、公式重算和分页可能因阅读器而异。

## 第三方文件

新产物的 sidecar 保存文件和结构化内容的 SHA-256，用于发现意外修改，不作为来源签名。旧版没有摘要的 sidecar 仍可读取、做只读结构检查和 PDF 实际预览，但无法确认文件与 sidecar 一致时不直接编辑；请先核对原文，再明确生成一个新文件。校验不会因新版模板变化而把旧文件判为损坏。

结构化编辑只面向带有 Orca sidecar 的产物。第三方复杂 Office 文件可能包含宏、SmartArt、嵌入对象、主题扩展或未知 OOXML 部件；在无法证明可以安全保留这些内容时，工具会明确拒绝修改，而不会声称实现了像素级或全保真 Office 编辑。原文件不会被覆盖。
